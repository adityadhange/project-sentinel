## 2. Registry Governance

This registry is a declarative roster of active specialist capabilities. It is subordinate to the authoritative DPR and the root control plane.

- The registry is a reference artifact, not a competing source of architectural authority.
- Capability classes define operational scope; they do not alter root invariants.
- Role activation is valid only when the underlying kernel and control-plane documents remain authoritative.
- Changes to registry membership or status should be reconciled through the architecture change proposal pathway.

## 3. Normalization Notes

- Prefer the `SKL-*` identifier format for specialist roles when the skill is treated as an active system capability.
- Keep `co-developer` as an offline advisory role unless explicitly promoted to a live execution role.
- Use this file to track the current fleet topology and to anchor role assignment logic in the control plane.
